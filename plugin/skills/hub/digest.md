# 每天汇总（收到 `kind` 是 `digest` 的事件时）

用户在设置页设了早上 / 晚上几点汇总（`config.json` 的 `digest`），到点引擎交一条 `source` 是 `chief`、`kind` 是 `digest` 的事件，`why` 是 `morning` 或 `evening`。用户自己说「汇总一下」也照这个写（不带 `--event`）。

1. `chief digest --event N` 拿材料（JSON，一次给全，不用再跑别的命令）：
   - `counts`：各有几件；`asks` 开着的要你定；`outbox` 待发出（`failed` 是没发出去的）；`waitingYou` 等用户的事；`due` 已过期和两天内到期的；`blocked` 卡住的；
   - `changed`：上一份汇总以后有进展的事（`recent` 是那以后的几句进展）；`events`：这段时间进来几条、哪些来源；
   - `held`：免打扰时引擎没弹的提醒（回复没发出去、Slack 登录失效、会话在等你回答……）；`quiet`：现在是不是免打扰。
2. 在本会话里写一段，标题 `**📋 chief · 早上的汇总**`（晚上的写「晚上的汇总」），下面按这个顺序，空的整段不写：
   - **要你定**：每条一行，事情标题 + 要定什么。
   - **待发出**：回谁、一句摘要；没发出去的写原因。
   - **快到期 / 卡住的**：标题 · 截止日或阻碍。
   - **这段时间**：有进展、办完的事每件一行；进来几条消息（按来源）。
   - **免打扰时没弹的**：每条一行。
   全都空就写一行「没有要你管的」。每件一行、话短；不写 chief 自己的编号（用标题说清是哪件）。最后一句告诉他去面板「要你」页处理。
3. 推送：有要你定或待发出、并且 `quiet.quiet` 是 false，推一条「早上的汇总：N 件要你定、M 条待发出」；免打扰中、或没什么要他动手的，不推。
4. 汇总只是念给他听：不新开问题（开着的已经在面板上了）、不派活、不改事情。
5. `chief mark N noted`（理由「早上的汇总」），`chief cursor N`。
