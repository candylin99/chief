# 面板指令（以「chief：」开头的话）

用户在面板上点按钮，面板替他往本会话发一句「chief：…」。这些话就是用户本人的操作，照下表办。

| 收到 | 你做 |
|---|---|
| 「chief：问题 #Q 照建议办」 | 面板已经替你 `chief ask answer` 记下了，不用再 answer。`chief ask show Q` 看问题和建议，再用 `send_message` 告诉那件事的会话：「关于 #T：用户同意你的建议：<suggest>，照办。」 |
| 「chief：问题 #Q 的回答：…」 | 面板已经记下了，不用再 answer。`chief ask show Q` 看问题，用 `send_message` 告诉那件事的会话：「关于 #T 的问题『<question>』，用户的决定：<原话>。照这个继续。」 |
| 「chief：问题 #Q1、#Q2… 都照建议办」 | 面板已经逐个记下了。每个 `chief ask show Q` 看建议，同一件事的合成一条 `send_message` 告诉那件事的会话：「关于 #T：用户同意你的这几条建议：<suggest 1>；<suggest 2>。照办。」 |
| 「chief：问题 #Q 不用问了」 | 面板已经记下了（`dismissed`）。`chief ask show Q` 看是什么，用 `send_message` 告诉那件事的会话：「关于 #T 的问题『<question>』，用户说不用问了：这件不做，接着做别的。」以后同类的事少问一点；他连着几次对同一类问题说不用问了，问他要不要写成规矩。 |
| 「chief：问题 #Q 的回答撤回了」 | 用户撤回了刚才的回答（或「不用问了」），问题回到等他定，面板已经改好了。如果你已经把那个回答转告了会话，用 `send_message` 告诉它：「关于 #T 的问题『<question>』，用户撤回了刚才的决定，先别照那个做，等他重新定。」还没转告就什么都不用做。 |
| 「chief：回复 #R 你改过再发的」 | 用户在面板上改了稿子才发。`chief reply list --all` 找到 R，对比 `original`（原稿）和 `body`（他改后的）。能概括成一条通用写法（删短了、换了语气、去掉了某类内容），就 `chief rules propose`（text 写成写法规矩，basis 写「你在一条回复里把『…』改成了『…』」），在「要你」页等他采纳；只改了事实或错字的不提议。不用跟用户说话，提议了才说一句「根据你改的稿子提议了一条写法」。 |
| 「chief：回复 #R 重写：…」 | `chief reply list --all` 找到 R（它的 `event` 是 N、`thing` 是 T）。用 `send_message` 告诉那件事的会话：「你给 <谁> 写的回复（事件 #N），用户的意见：<原话>。改好重新发『chief 回复 #N』。」 |
| 「chief：导入现在在做的事」 | Read 本 skill 目录下的 `import.md`，照它办。 |
| 「chief：重读规则」 | 用户更新了插件。用 Skill 工具重新调用 `chief:hub`，照新读到的办。不重新开张、不重挂 Monitor。只回一句「规则重读好了」，和之前有明显不一样的地方顺带说一句。 |
| 「chief：问一遍各事情的最新进展」 | `chief thing list`，对每件有会话、还没办完的，用 `send_message` 发：「chief 消息中心想知道 #T 的最新情况：请按『chief 进展 #T』的格式（进展 / 下一步 / 阻碍 / 结果 / 截止）回一条。」没会话的（导入的 Jira / PR）自己用 `acli`（或 `twg`）、`gh` 查一下现状，`chief thing update`。都回来以后，照「我在忙什么」给用户汇总一次。 |
| 「chief：批注（N 条）」+ 编号列表 | 逐条办：<br>• 「关于【事情 #T …】：…」：`send_message` 转给那件事的会话：「用户关于 #T 说：<原话>。」<br>• 「关于【要你定 #Q …】：…」：当成用户对这个问题的回答（`chief ask answer Q`），再转告会话。<br>• 「关于【待发出 #R …】：…」：当成对这条稿子的意见，`chief reply redo R`，转给写稿的会话让它重写。<br>• 不指定的：对上是哪件事再转；对不上就问用户。<br>汇报标题 `**🖱 面板 · 批注 3 条**`，下面每条一行（压测 → 改报告；Joe 那个先不回）。目标会话权限模式和本会话不一样时，提醒用户这条会被扣住、要他自己去说。 |
| 「chief：转告事情 #T：…」 | `send_message` 把原话转给那件事的会话：「用户关于 #T 说：<原话>。」它回了进展照常记。 |
| 「chief：自动分发事件 #N」 | 照「来了新消息」办这一条。 |
| 「chief：为事件 #N 新开会话」 | 照「派活」第 3 点直接开新会话。 |
| 「chief：把事件 #N 分发到会话 S（标题）」 | 送进会话 S，后面照「派活」的收尾。 |
| 「chief：打开会话 S（标题）」 | 只回一行可点的链接：`[标题](#S)`（S 是 `local_…` 那个会话编号，原样照抄，不要自己编）。 |
| 「chief：事情 #T 不做了（…）」 | `chief thing update T --status dropped`（标准输入：用户说不做了），`send_message` 告诉那个会话停下、不用再汇报。 |
| 「chief：判断 #N 错了：…」 | 用户在进度页的「最近」纠正了你对事件 #N 的判断。<br>1. `chief show N` 看原消息，想清楚错在哪。<br>2. 还来得及补救的（比如该派活却只记了一笔），照用户说的马上办。<br>3. `chief rules propose`，标准输入 `{"text": "<一句话规矩>", "basis": "你在一条判断上纠正：<用户原话>"}`。规矩要具体到能照着做（谁、在哪、什么情况、怎么办）；已有规矩说过的不重复提。<br>4. 跟用户说一句：「已改正；提议了一条规矩，在「要你」页等你采纳」。 |
